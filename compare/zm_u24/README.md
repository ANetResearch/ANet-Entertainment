# 工作流对比：`minimax_h3_adl_int8` 与 `minimax_h3_zm_u24`

短片《未熄》电影版（`episodes/ep14`）里挑了 6 个有人物、有动作的镜头，用**完全相同的请求**在 `minimax_h3_zm_u24`（“H3 多图多音频生视频（升级画质）”）上各重新生成一条，和原来在 `minimax_h3_adl_int8`（“H3 官方 INT8 非剪枝版”）上生成的那条对比。

相同的输入：提示词全文、随机种子、时长、分辨率（`768p横`）、参考图的张数、顺序和 JPEG 字节（同一份缓存文件）。每条的完整请求内容和请求体的 SHA-256 记在 `clips/ep14_sNN_zm_u24.json`，原任务号在 `baseline_task_id`。

## 结果

| 镜头 | 内容 | 拉普拉斯方差（越大越锐） | 高频能量占比 | 视频码率 kb/s | 生成耗时 s | 输入图 |
|---|---|---|---|---|---|---|
| s05 | 结霜的居住走廊里，阿牧把手掌贴在结冰的供暖管上，回头看了看身后裹着毯 | 293 → **412** | 4.1% → **6.3%** | 7852 → 7511 | 259 → 285 | 3 |
| s41 | 金老板和阿牧合力把一只钢箱抬上驾驶室，箱盖合上前，里面的点火核心泛着 | 93 → **255** | 1.5% → **4.1%** | 7971 → 11577 | 275 → 264 | 2 |
| s51 | 小满扑上去从后面抱住“螺丝”的机身，脚跟蹬着冰面往回拽，朝它喊 | 64 → **132** | 1.9% → **3.3%** | 7988 → 9167 | 289 → 298 | 4 |
| s56 | 阿牧扛着钢箱在漆黑的发动机廊道里狂奔，应急灯一盏盏从头顶掠过 | 40 → **53** | 1.9% → **2.0%** | 7998 → 9623 | 267 → 530 | 2 |
| s68 | 冰原上，几支素不相识的车队碰了头，人排成一列传递冷却罐，队伍中间夹着 | 94 → **98** | 2.0% → **2.3%** | 7985 → 11986 | 269 → 272 | 3 |
| s80 | 小满又哭又笑，蹲下来伸出手掌 | 229 → **346** | 3.6% → **5.6%** | 7570 → 7448 | 315 → 317 | 4 |

左边是 `adl_int8`，右边是 `zm_u24`。两项清晰度指标都是按每秒 4 帧取灰度帧计算后取中位数，脚本是 `tools/ab_measure.py`，原始数字在 `metrics.json`。

- **`zm_u24` 六个镜头全部更锐。** 构图几乎一致的 s05、s51、s80 上，拉普拉斯方差高 40%–105%；100% 放大看（`stills/s05_face_crop100.jpg`，左旧右新），发丝、皮肤纹理、衣料织纹都保留了下来，`adl_int8` 那条被抹平了。
- **两边输出规格相同**：都是 1344×768、24 帧、H.264。所以“糊”不是输出分辨率造成的。两个工作流的名称分别标明“INT8”和“升级画质”，差别最可能来自模型权重的量化，这一点是推断，没有办法从外部验证。
- **编码也有差别**：`adl_int8` 的视频码率基本卡在 8000 kb/s 左右；`zm_u24` 在细节多的镜头上给到 9000–12000 kb/s。音频反过来，185 对 128 kb/s。
- **价格相同**，都是 ¥0.05/秒（6 条共 ¥2.75）。`zm_u24` 生成更慢，单条 264–530 秒，原工作流是 259–315 秒。

## 需要注意

- **同一个种子在两个工作流上不会出同一个画面。** s05、s51、s56、s80 构图很接近，可以直接比；s41 和 s68 的调度不一样（s41 新版拍出了箱子里发红光的点火核心，旧版没有），这两条的指标差里混有内容差异。
- 每个镜头只有一条，共 6 对，是抽样，不是统计结论。
- 动作幅度大的 s56（奔跑）和 s68（传递罐子）提升很小，运动模糊占主导。
